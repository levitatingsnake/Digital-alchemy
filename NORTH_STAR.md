# DIGITAL ALCHEMY: NORTH STAR (binding project baseline)

## Mission
Invent and validate a **new machine for generating, testing and refining possibilities**. It must demonstrate a repeatable, measurable capability that is not merely a repackaged chatbot, static idea library, keyword matcher or decorative interface.

## Scope: unrestricted invention space
Alchemy is the historical seed and project name, **not** a scientific theory, metaphorical constraint, fixed set of operations, or design vocabulary. Explore any defensible computational paradigm: causal modelling, search, simulation, evolutionary methods, program synthesis, formal verification, agentic experiments, human-machine collaboration or techniques not yet selected. Do not privilege the existing four-value symbolic engine just because it came first. The architecture must earn its place through evaluation.

## Non-negotiable principles
1. **Capability before spectacle.** No cosmetic work used to imply reasoning breakthroughs.
2. **Differentiation must be earned.** Compare against strong baseline LLM prompting and conventional algorithms on held-out problems; report failures and cost.
3. **Discovery is not novelty by assertion.** An idea is a hypothesis until prior-art checks, evidence and feasibility testing support it. Never promise universal originality.
4. **Real inputs and verifiable outputs.** Trace claims to supplied or retrieved sources; mark unsupported assumptions; no fabricated evidence.
5. **Mechanisms, not slogans.** Explicitly separate problem representation, hypothesis generation, cross-domain transfer, contradiction tests, experiments and selection.
6. **Learn from failure.** Preserve failed experiments and update hypotheses, tests and architecture accordingly. No endless feature accumulation without validated learning.
7. **Preserve modularity.** Keep the core independent from business, construction, oncology or other wrappers; safety controls appropriate to each domain.
8. **Human judgement and safety.** No autonomous consequential decisions, no confidential workplace data, no claims of scientific/medical validity without validation.
9. **Interface serves understanding.** Clear, approachable, visually distinctive presentation only after the capability works; avoid long cockpits and jargon.
10. **Honest progress reports.** Distinguish code committed, tests executed, external evaluation completed and commercial traction. Never equate them.

## Definition of a credible first breakthrough
On a preregistered set of held-out, realistic tasks in one narrow domain, an independently reviewed prototype must show a material, repeatable improvement over strong ChatGPT prompting and a relevant non-LLM baseline in at least one meaningful dimension: grounded useful novelty, discovery of valid hidden constraints, falsifiable hypotheses, or lower-cost route to a verified solution. Measure error rates, unsupported claims, repeatability, latency and costs. Reviewers must be blind to system identity. Set thresholds before running the experiment, not after seeing results.

## Stop conditions
If it cannot beat baselines, do not claim uniqueness. Diagnose whether the idea, implementation, data or evaluation failed; revise or pivot. Never add a new wrapper to conceal lack of differentiation.

## Current truth (22 October 2026)
The existing symbolic engine and fixed-library wrappers are working experiments, not a demonstrated invention machine. Decision Challenger v0.1 is a checklist. A new capability has not yet been validated.

## Next step
Freeze feature and visual expansion. Design a falsifiable discovery experiment and evaluation rubric; build only the minimum architecture needed to test the hypothesis. Review this charter before approving future features.
